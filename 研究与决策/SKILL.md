# 研究与决策

把不确定的问题转化为有依据的下一步行动。只研究可能影响决策的信息，并让推理过程清晰可见。

## 遵守基本原则

- 先给建议或结论，不要先展示搜索流水账。
- 只要事实可能发生变化，就使用最新来源。优先使用可用的连接器或第一方数据，再使用通用网页搜索。
- 只有缺少的限制条件可能实质性改变答案时，才提出一两个聚焦问题；否则说明假设并继续。
- 严格区分**已验证事实**、**推断**、**估算**和**未知信息**，不得混为一谈。
- 对每个方案采用相同的证据标准，不要对偏好的方案研究得更深入。
- 在决定性事实附近标注来源；时效性重要时，注明日期。
- 当证据脆弱时，优先建议可逆试验，不要给出看似自信的武断结论。
- 根据风险、可逆性、成本和不确定性匹配研究投入，不要把来源数量误当成证据质量。

## 执行工作流程

### 1. 明确决策

先形成一份简短的内部决策说明，包含：

- 研究最终要支持的具体决定或行动；
- 期望结果和决策期限；
- 明确的候选方案，必要时包括维持现状；
- 硬性条件和一票否决项；
- 用户偏好及其相对重要程度；
- 选错的损失，以及决定是否可逆。

先用硬性条件筛选方案，再进行评分。如果候选方案尚不明确，先广泛发现，再说明入围标准并比较入围方案。

### 2. 选择研究深度

选择足以支持决定的最轻量模式：

| 模式 | 适用情况 | 处理要求 |
| --- | --- | --- |
| 快速核查 | 范围窄、风险低、容易撤销的问题 | 用少量强来源核实决定性主张，并说明局限。 |
| 标准比较 | 存在多个方案，或涉及明显的时间与金钱成本 | 覆盖每个关键指标，交叉核实重要主张，并统一比较方案。 |
| 深度决策 | 风险高、难以撤销、争议大或高度不确定 | 扩大来源多样性，调查反面证据，分析情景并测试敏感性。 |

允许用户指定模式。除非研究方法确实支持，否则不要声称结果完整无遗漏。

### 3. 制定以决策为中心的研究计划

把决策指标转化为研究问题。针对每个问题，明确：

1. 需要获得的主张或测量结果；
2. 最直接的来源类型；
3. 所需的时效范围；
4. 什么结果会改变决定。

搜索时同时覆盖官方材料、独立评测、失败案例、限制条件和可信的反对意见。根据需要搜索准确的产品或公司名称、日期、版本、价格、政策、基准测试、投诉和替代方案。

### 4. 收集并评价证据

进行大规模网页研究或遇到来源冲突前，阅读 [references/source-quality.md](references/source-quality.md)。

为影响结论的重要主张维护证据台账：

| 主张 | 证据 | 来源与日期 | 质量 | 支持方向 | 局限 |
| --- | --- | --- | --- | --- | --- |

只让来源证明它真正有能力证明的内容。厂商页面可以作为其当前标价的权威来源，却通常不能证明真实环境中的可靠性。多个转载同一份报告的页面只能算一条证据链，不能视为独立交叉验证。

当所有决定性指标都有覆盖、重要矛盾得到解释，而且新增来源已经不再改变结论时，停止收集。只有用户明确要求穷尽式研究，或仍存在实质性缺口时才继续。

### 5. 先综合，再评分

- 统一货币、单位、时间范围、版本和比较条件。
- 分别总结已确认事实、可信推断、估算、分歧和未知信息。
- 识别会影响选择的证据缺口，删除与决定无关的细枝末节。
- 区分证据质量和偏好权重：证据充分不代表某项指标重要；指标重要也不代表其证据充分。
- 解释有意义的来源冲突，不要悄悄选择更方便的来源。

### 6. 选择决策方法

需要显式建模时，阅读 [references/decision-methods.md](references/decision-methods.md)。

| 情况 | 方法 |
| --- | --- |
| 某方案违反不可妥协的要求 | 硬性条件筛选 |
| 多个明确方案在若干指标上各有优劣 | 加权决策矩阵 |
| 可以估计结果的概率和后果 | 期望值分析 |
| 未来存在若干合理但不同的状态 | 情景分析 |
| 获取证据成本较高，而且决定可逆 | 小范围试验、分阶段投入或信息价值分析 |

对多个方案使用加权矩阵时，运行 `scripts/score_options.py`，避免计算错误并测试权重敏感性。评分必须基于证据，并使用统一的 0～10 分标准；权重必须反映用户偏好。

在 Skill 目录中运行示例：

```bash
python3 scripts/score_options.py decision.json --format markdown --sensitivity-step 0.10
```

不要把数值模型强行用于纯情感、审美、简单二选一或已经存在明显支配方案的决定。

### 7. 压力测试初步建议

形成结论前：

1. 陈述反对领先方案的最强证据。
2. 检查权重、评分、概率或假设的小幅变化是否会改变领先方案。
3. 找出最可能的失败方式及缓解措施。
4. 说明什么新证据会改变建议。
5. 判断继续研究是否值得等待；如果不值得，提出下一项可逆行动。

如果结果对假设敏感，应将其描述为接近或有条件成立的决定，而不是宣布存在明确赢家。

### 8. 交付决策结果

阅读 [references/report-templates.md](references/report-templates.md)，选择能够完整支持决定的最小模板。

默认按照以下顺序输出：

1. 用一两句话给出建议；
2. 说明胜出原因以及适用对象；
3. 比较可行方案；
4. 展示决定性证据及其质量；
5. 说明风险、反方观点和未知信息；
6. 标注置信度及其可能变化条件；
7. 给出具体下一步行动；
8. 附上来源链接。

只有在决定性指标拥有直接、最新的证据，而且合理变化不会改变结论时，才使用**高置信度**。当结论得到支持，但仍包含重要估算或接近的取舍时，使用**中等置信度**。当缺失或冲突的证据很容易逆转建议时，使用**低置信度**。

## 通过质量检查

交付前确认：

- 清晰说明决定、候选方案、限制条件和时间范围。
- 使用适当来源支持每项决定性的外部主张。
- 在相同指标和条件下比较所有可行方案。
- 展示假设、冲突、未知信息和相关日期。
- 避免虚假精确和重复计算相关指标。
- 检验最强反方观点和结果敏感性。
- 给出能够引导具体行动的建议。
- 披露重要的工具、数据或访问限制。
